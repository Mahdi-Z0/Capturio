<objective>

## Goal

Reach the bar without finding it. Three global shortcuts, each changeable in Settings, each reported
truthfully when Windows or another program already owns the combination.

## Purpose

v0.7 item 1. The bar can be hidden, and the only ways back today are a tray icon and relaunching the
app. Neither works (see Findings), so this phase fixes the routes back as well as adding the shortcut.

## Output

| Action | Default | What it does |
| --- | --- | --- |
| Start or stop recording | `Ctrl+Shift+R` | Unchanged from 05-02 — the bar decides, using what it has selected |
| Show or hide the bar | `Ctrl+Alt+Shift+B` | Same as a click on the tray icon |
| Record a region | `Ctrl+Alt+Shift+R` | Opens the region selector; the recording starts the moment the drag ends |

</objective>

<findings>

Found while reading the code for this plan, before any change:

1. **The tray icon is never created.** `createTray()` is called in exactly one place: inside
   `toggleBar()`, whose only callers are the tray's own click and menu. It has been this way since
   `6213266`. Evidence beyond the code: Windows 11 records every notification icon it is handed under
   `HKCU\Control Panel\NotifyIconSettings`, and there is no Capturio or Electron entry on this machine
   although the installer was run. Consequence: **Hide the bar strands the app** — running, no window,
   no tray, and (finding 2) no way to get it back by relaunching.
2. **No single-instance lock.** Launching Capturio from the Start menu while it runs starts a second
   recorder with a second bar, which loses the `Ctrl+Shift+R` race to the first.

Both are in scope: "reach the bar" is the goal, and these are the two routes back that already exist.

</findings>

<design>

## Defaults

`Ctrl+Shift+R` stays: it is what the user already knows. The two new defaults add Alt, because a
global shortcut takes the combination away from *every* program, and `Ctrl+Shift+<letter>` is
routinely bound (Save As, bookmarks, private windows). Hardly anything uses `Ctrl+Alt+Shift`.
"Record a region" is the record shortcut plus Alt: *record, but choose where first*.

## Honesty

- `globalShortcut.register` returns false when the combination is held elsewhere. A new combination is
  **probed before it is saved**; if it does not take, nothing changes and the user is told which
  combination was refused. A saved combination that fails at startup (another program got there
  first) shows as **not working** in Settings and in Help, and is logged, following the precedent of
  `[shortcut] Ctrl+Shift+R is taken`.
- While a combination is being recorded in Settings, **all** of the app's shortcuts are suspended —
  otherwise pressing the current one would fire it instead of reaching the page. Resumed on confirm,
  cancel, blur, and (as a guarantee) when the window hides or closes.
- A combination another program has registered never reaches the page at all. Settings says so in one
  line rather than leaving someone pressing keys at a control that seems dead.

## Validation, once

`src/main/accelerator.cjs` is the single validator, CommonJS and pure like `recordingPath.cjs`, so
`scripts/verify-shortcuts.cjs` exercises the shipped function. Rules:

- Modifiers `Control`, `Alt`, `Shift`, `Super`, each at most once, written in that order.
- Exactly one key from: `A`–`Z`, `0`–`9`, `F1`–`F24`, `Space`, `Insert`, `Delete`, `Home`, `End`,
  `PageUp`, `PageDown`, `Up`, `Down`, `Left`, `Right`, `PrintScreen`. Punctuation is left out:
  Electron maps it through the keyboard layout, so what is shown and what fires can differ.
- A key that types or moves needs `Control`, `Alt` or `Super`. Shift alone would steal capitals.
  `F1`–`F24` and `PrintScreen` may stand alone.
- No two actions share a combination.

## Settings file

v3 → v4 adds `shortcuts: { record, bar, region }`, each a canonical string or `null` (off). Each field
is validated independently, as the other fields already are; a v3 file gains the defaults.

</design>

<acceptance_criteria>

- **AC-1** The three defaults work in the built app with the bar visible *and* hidden. The region
  shortcut starts recording the dragged region with no further click; Esc in the selector starts
  nothing.
- **AC-2** A combination another process holds is refused when chosen, with the previous one still
  working, and shows as not working when it was taken before launch.
- **AC-3** Changing a shortcut takes effect immediately and survives a restart. Backspace turns one
  off; Esc cancels. The old combination stops firing.
- **AC-4** The tray icon exists from launch, and the NotifyIconSettings entry appears.
- **AC-5** A second launch exits and brings the first instance's bar back.
- **AC-6** `npm run verify` includes the shortcut validator, run against the shipped module.
- **AC-7** `npm run build` and `npm run lint` pass.

</acceptance_criteria>
